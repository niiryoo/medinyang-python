# ADR-008: 근거 인용 표기와 검색 지표의 한계

## 관측

의료 RAG에서 근거 표기는 선택이 아니다. 답변이 어느 문서에서 나왔는지 추적할 수 없으면
검증도 정정도 불가능하다. 기존 구현에는 인용이 없었다.

동시에 이 프로젝트의 측정은 전부 **검색 단계**에 머물러 있었다. Precision@5가 0.7645라는 것이
사용자 질문의 76%에 답할 수 있다는 뜻인지 확인된 적이 없다.

## 원인

`format_docs`가 문서를 구분자로 이어붙이기만 해서 LLM이 문서를 개별 단위로 지칭할 수단이 없었다.
프롬프트에도 근거 표기 규칙이 없었다.

## 고려한 대안

| 안 | 장점 | 단점 |
|---|---|---|
| (a) 인용 없이 유지 | 변경 없음 | 의료 도메인에서 결함 |
| (b) **문서에 `[n]` 부여 + 프롬프트 규칙** | 구현 단순, 기계적 검증 가능 | 모델이 규칙을 부분적으로만 지킴 |
| (c) 문장 단위 근거 매칭 (생성 후 정렬) | 정밀 | 별도 모델 필요, 이 규모에 과함 |
| (d) LLM judge로 faithfulness 채점 | 내용 충실도까지 평가 | 점수가 주관적·비재현적, 비용 |

## 결정

(b). `format_docs`가 `[1]`~`[5]`를 붙이고, 프롬프트 규칙 6번이 문장마다 번호를 요구한다.

**검증은 LLM 채점 없이 정규식과 문자열 비교만 쓴다.**

1. 답변에서 `\[(\d+)\]` 추출
2. 번호가 실제 검색 결과 범위 안인지 확인
3. 그 번호가 가리키는 문서의 `disease_name`을 골든셋 정답과 `==` 비교

이 방식이 재는 것은 **"인용한 문서의 라벨이 맞는가"**이지 **"그 문서가 그 문장을 뒷받침하는가"**가
아니다. 근거 품질의 하한선이며, 통과했다고 충실하다는 뜻은 아니다.

## 검증

골든셋에서 의도별로 균등 표집한 44건. 인용 규칙 유무를 A/B로 비교했다.

### 인용 규칙이 거부를 늘리는가

| | 거부 |
|---|---|
| 인용 규칙 있음 | 19/44 (43.2%) |
| 인용 규칙 없음 | 21/44 (47.7%) |

늘리지 않는다. 오히려 약간 줄었다. 규칙 추가가 모델을 보수적으로 만들었다는 가설은 기각된다.

### 인용 품질

| 지표 | 값 |
|---|---|
| 유효 인용률 | 1.0000 |
| 인용 질환 일치율 | 1.0000 |
| 인용 의도 일치율 | 0.8952 |
| 문장 인용률 | 0.5968 |
| 답변당 인용 | 2.8개 |

**존재하지 않는 번호를 지어낸 사례가 없다.** 그리고 인용된 문서는 전부 정답 질환이었다 —
이 표본에서 deceptive grounding은 관측되지 않았다.

검색 단계의 질환 일치율이 0.8718(상위 5건 중 약 13%가 다른 질환)인데 인용은 1.0인 이유는
아래 거부 분석에서 설명된다.

## 발견: 라벨 일치는 답변 가능성이 아니다

거부 19건을 검색 품질로 나눠보면 두 갈래다.

| 질환 일치율@5 | 거부 | 답변 | 거부율 |
|---|---|---|---|
| 0.0 | 5 | 0 | 1.00 |
| 0.4 | 1 | 0 | 1.00 |
| 0.8 | 1 | 2 | 0.33 |
| 1.0 | 12 | 23 | 0.34 |

**검색이 완전히 빗나가면(6건) 모델은 100% 거부한다.** 다른 질환 문서를 근거로 답을 지어내지
않는다는 뜻이고, 인용 질환 일치율 1.0이 여기서 나온다.

그런데 **거부 19건 중 검색 실패로 설명되는 건 6건뿐이다.** 나머지 13건은 Precision@5가 1.0인데도
거부됐다. 실제 질문을 보면 이유가 분명하다.

```
"후천성 면역결핍증을 검진받기 위해선 어떤 의료기관을 찾아가야 하나요?"
   → 문서에 기관 이름이 없음. 프롬프트 규칙 1이 임의 생성을 금지

"발진티푸스 약물 치료의 효과는 일반적으로 얼마나 지속되나요?"
   → 문서에 기간 수치가 없음

"풍진이 발생하는데 가장 큰 요인은 무엇인가요?"
   → 문서는 원인을 나열만 하고 순위를 매기지 않음
```

`(질환, 의도)` 라벨이 정확히 맞는 문서라도 **그 질문에 답할 정보를 담고 있지는 않다.**

**따라서 ADR-000에서 정의한 Precision@5는 답변 가능성의 상한을 과대평가한다.**
Precision@5 = 0.7645인 구성에서 실제 답변율은 25/44 = **0.5682**다.

이건 지표의 결함이라기보다 **지표가 재는 대상의 경계**다. 검색 지표는 "관련 문서를 가져왔는가"를
재고, 답변 가능성은 그 위의 별개 층이다. 이 프로젝트가 그 경계를 넘지 않았다는 사실을
수치로 확인한 것에 의미가 있다.

## 트레이드오프

**문장 인용률이 0.5968이다.** 규칙은 모든 문장에 번호를 요구하는데 60%만 지킨다.
프롬프트로 강제하는 방식의 한계이며, 완전 준수가 필요하면 후처리 검증과 재생성이 필요하다.

**표본이 44건이다.** 비용(gpt-4o, TPM 30,000 제약)과 시간 때문에 전량 220건을 돌리지 않았다.
거부율 43.2%의 95% 신뢰구간은 대략 ±15%p이므로 정밀한 값이 아니다.

**내용 충실도는 여전히 미측정이다.** 인용한 문서가 그 문장을 실제로 뒷받침하는지는
LLM judge나 사람이 필요하고, 이 프로젝트 범위 밖으로 뒀다.

## 2차 효과

**ADR-004의 결론이 보강된다.** 거기서 재순위화 점수로 폴백 게이팅을 만들려다 실패했는데
(AUC 0.586), **LLM이 이미 게이팅을 하고 있었다.** 검색이 완전히 빗나간 6건에서 100% 거부했다.
명시적 임계값 장치를 못 만든 것이 실질적 손실이 아니었다는 근거가 된다.

다만 이 게이팅은 완벽하지 않다. 질환 일치율 1.0인 12건도 거부했으므로 **거부 사유가
근거 부족과 답변 불가로 섞여 있고, 시스템은 둘을 구분하지 못한다.** 폴백 프롬프트가
두 경우에 같은 방식으로 답하는데, 전자는 "자료가 없다"이고 후자는 "질문 범위 밖"이라
안내가 달라야 한다.

**답변율 56.8%는 서비스 관점에서 낮다.** 나머지는 폴백(일반 LLM)으로 넘어가므로
사용자가 받는 답의 상당수가 문서 근거 없이 생성된다. ADR-005에서 폴백 경로에 안전 지침을
복구한 것이 예상보다 중요한 수정이었다는 뜻이다.
