# ADR-002: 하이브리드 검색(BM25 + dense) 도입 검토 후 기각

## 관측

의도 일치율이 0.58에서 정체돼 있다. 의도 라벨("정의", "원인", "치료" 등)은 문서 앞머리에
**문자열 그대로** 박혀 있으므로, 어휘 일치를 보는 sparse 검색이 dense가 놓치는 것을
잡아줄 것이라 예상했다.

## 원인

dense 임베딩은 의미를 압축하는 과정에서 **정확한 단어 일치 정보를 잃는다.**
"예방" 질문에 "치료" 문서를 주는 실패가 여기서 나온다고 봤다.

## 고려한 대안

| 안 | 장점 | 단점 |
|---|---|---|
| (a) dense 단독 (현행) | 단순 | 어휘 일치 신호 없음 |
| (b) **BM25 + dense, RRF 융합** | 두 신호 결합. 업계 표준 조합 | 코퍼스를 메모리에 적재, 가중치 튜닝 필요 |
| (c) dense + 메타데이터 필터 | 의도를 직접 제약 | 질의의 의도를 알아야 함 (분류기 필요) |

## 결정

**(b)를 측정한 뒤 기각.** dense 단독을 유지한다.

(c)는 이 시점에 의도 분류기가 없어 불가능했다. ADR-006에서 다시 다룬다.

## 측정 과정에서 발견한 오류

첫 실행에서 `bm25_weight=0.25`로 돌렸더니 하이브리드가 dense와 **완전히 동일한** 결과를 냈다.
버그를 의심했으나 RRF 산수의 문제였다.

```
RRF 점수 = weight / (k + rank),  k = 60

BM25 1위 : 0.25 / (60 + 1)  = 0.00410
dense 20위: 0.75 / (60 + 20) = 0.00938
```

**BM25가 1위로 올린 문서조차 dense의 20위보다 낮다.** 가중치 0.25에서 BM25는
수식상 아무 영향도 줄 수 없었다. 실제로 상위 20개 집합이 dense와 일치함을 확인했다.

가중치 0.5로 다시 측정했다.

## 결과

| | Precision@5 | 의도@5 | 질환@5 |
|---|---|---|---|
| dense 단독 | 0.5264 | 0.5845 | 0.9091 |
| +BM25(0.5) | 0.3955 | 0.4627 | 0.7909 |

대응표본 비교: dense가 **+13.09%p** 우위, CI [+9.96, +16.22], 유의.

한국어 토크나이저(조사 제거)도 붙여봤으나 공백 분리 대비 차이가 노이즈 범위였다.

## 왜 나빠졌는가

의도 라벨은 **모든 문서에 다 들어 있다.** "치료" 문서에도 "정의" 문서에도
같은 어휘가 반복된다. BM25 관점에서 이런 단어는 문서 변별력이 거의 없는데,
질의는 짧아서 그 소수의 단어에 점수가 좌우된다. 결과적으로 BM25는
**질환이 다른 문서를 대량으로 끌어올렸다** (질환 일치 0.9091 → 0.7909).

sparse 검색이 유용한 조건은 코퍼스에 희소한 고유명사가 흩어져 있을 때다.
이 코퍼스는 반대로 **모든 문서가 같은 어휘 틀을 공유한다.**

## 트레이드오프

기각으로 **어휘 정확 일치가 필요한 질의를 포기했다.** 약품명이나 검사명처럼
철자가 중요한 질의에서 dense가 놓칠 여지가 남는다. 다만 이 골든셋에는
그런 질의 유형이 드물어 측정으로 확인할 수 없었다. 코퍼스가 바뀌면 재검토 대상이다.

## 2차 효과

BM25를 뺀 덕분에 **코퍼스 전량을 메모리에 올리지 않아도 된다.** 102,245건 인덱싱에
24~45초가 걸렸고, 프로덕션이라면 프로세스마다 이 메모리를 중복 점유하게 된다.

더 중요한 소득은 방법론 쪽이다. **가중치를 바꾸지 않고 첫 결과만 봤다면
"하이브리드는 효과 없음(중립)"이라고 잘못 결론 낼 뻔했다.** 실제로는
설정이 잘못돼 실험이 성립하지 않은 상태였다. 이후 모든 실험에서
"차이 없음"이 나오면 먼저 실험이 성립했는지부터 확인한다.
