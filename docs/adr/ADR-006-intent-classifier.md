# ADR-006: 질의 의도 분류기 + 메타데이터 필터

**상태: 채택** — Precision@5 0.5564 → 0.7536 (+19.73%p, CI [+14.25, +25.20], 유의)

## 관측

세 번의 실험이 같은 곳에서 멈췄다.

| 축 | E1 ada-002 | E4 재순위화 | 변화 |
|---|---|---|---|
| 질환 일치@5 | 0.8527 | 0.9336 | +8.09%p (유의) |
| 의도 일치@5 | 0.5555 | 0.5982 | +4.27%p (경계) |

임베딩 교체(ADR-001), 하이브리드(ADR-002), 재순위화(ADR-003) 중
의도 일치율을 유의하게 올린 것이 하나도 없다.

두 축을 곱해보면 구조가 드러난다.

```
질환 0.9336 × 의도 0.5982 = 0.5585      실측 Precision@5 = 0.5564
```

거의 정확히 일치한다. 두 오차가 독립적으로 곱해지고 있다.

## 원인

의도 라벨이 문서 본문 앞머리에 문자열로 녹아 있을 뿐, 질의의 의도와 문서의 의도를
대조하는 장치가 파이프라인 어디에도 없다.

검색기는 "예방법이 뭐야?"와 "치료법이 뭐야?"를 벡터 공간에서 가깝게 놓는다.
둘 다 같은 질환에 대한 짧은 의문문이고 의미적으로 실제로 가깝다.
검색기 성능 문제가 아니라 표현 설계 문제다.

## 고려한 대안

| 안 | 장점 | 단점 |
|---|---|---|
| (a) 의도를 본문에서 더 강조 | 인덱스만 재빌드 | 세 실험이 실패한 축을 같은 방식으로 또 미는 것 |
| (b) 의도별 인덱스 분리 | 필터 자동 | 인덱스 11개, 오분류 시 복구 불가 |
| (c) **질의 의도 분류 → 메타데이터 필터** | 오분류해도 복구 여지 | 분류기 학습·서빙 필요 |
| (d) 의도별 프롬프트 분기 | 생성 품질 향상 | 검색 자체는 그대로 |

## 결정

(c). 질의를 11개 의도 중 하나로 분류하고 FAISS `intention` 메타데이터 필터를 건다.

**분류기는 TF-IDF + 로지스틱 회귀.** ADR 초안에는 임베딩 + 로지스틱 회귀를 적었으나,
어휘 신호가 강한 문제("무엇인가요" / "왜 생기나요" / "어떻게 치료")라 먼저 싼 쪽을 쟀다.
정확도 0.8706이 나와 임베딩 API를 쓸 이유가 없어졌다. **API 비용 0원, 학습 수 초.**

학습 데이터는 질문 파일 86,352건의 기존 `intention` 라벨을 그대로 썼다.
의도당 최대 3,000건 층화 추출로 30,517건을 학습했고, **골든셋 220건은 제외**했다.

## 검증

### 분류기 (홀드아웃 6,104건)

```
accuracy   0.8706
macro F1   0.8766
```

주요 혼동은 전부 의미적으로 인접한 쌍이다 — 검진↔진단(113건), 치료↔약물(97건),
정의↔원인(86건), 예방↔식이·생활(75건). 모델 결함이라기보다 라벨 정의의 경계가 모호하다.

### 검색 (골든셋 220건)

| | Precision@5 | 의도@5 | 질환@5 | MRR |
|---|---|---|---|---|
| E4 재순위화 (직전 최고) | 0.5564 | 0.5982 | 0.9336 | 0.6353 |
| **E6 의도 필터** | **0.7536** | 0.8773 | 0.8655 | 0.7674 |

대응표본 비교 (E6 − E4):

| 지표 | 차이 | 95% CI | 판정 |
|---|---|---|---|
| Precision@5 | +19.73%p | [+14.25, +25.20] | 유의 |
| 의도 일치@5 | +27.91%p | [+22.08, +33.74] | 유의 |
| 질환 일치@5 | **-6.82%p** | [-9.89, -3.75] | 유의 |

## 트레이드오프

**질환 일치율 하락이 유의하게 측정됐다.** 공짜가 아니다.

필터가 후보를 코퍼스의 약 1/11로 줄이므로, 같은 20건을 채우려면 벡터 순위를 훨씬
깊이 파고들어야 한다. 그 구간은 질환 적합도가 낮다. `fetch_k`를 20에서 8,000으로
올려야 필터 후에도 20건이 남는다.

그리고 **분류가 틀리면 정답 문서가 검색 대상에서 아예 빠진다.** 실패 모드가
"부정확한 답변"에서 "답변 불가"로 바뀐다. 실제로 `fetch_k=2000`에서 220건 중
2건이 검색 결과 0건이 됐다. `fetch_k=8000`으로 해소했고, 그래도 비면 필터 없이
재시도하도록 넣었다.

### 완화책 두 가지 모두 기각

ADR 초안에 적은 완화책이 **둘 다 측정에서 깨졌다.**

**soft filter (상위 2개 의도 허용)** — Precision@5 0.6027. hard filter보다 나쁘다.
의도를 2개 허용하면 의도 일치율이 0.8773에서 0.6818로 떨어져, 얻는 것보다 잃는 게 크다.

**신뢰도 게이팅 (낮으면 필터 해제)** — 걸수록 나빠진다.

| 임계값 | Precision@5 |
|---|---|
| 없음 | **0.7536** |
| 0.5 | 0.7500 |
| 0.7 | 0.7182 |

임계값 없음이 0.7 대비 +3.55%p 우위, CI [+0.54, +6.56], 유의.

이유는 산수로 설명된다. 신뢰도가 낮은 질의에서 필터를 끄면 무필터 성능(약 0.53)으로
돌아간다. 반면 불확실해도 필터를 걸면 대략 0.7 × 0.87 ≈ 0.61이다.
**분류기가 틀릴 것 같을 때조차 정보가 없는 것보다 낫다.**

### 신뢰도 자체는 쓸 만한 신호였다

ADR-004에서 리랭커 점수로 폴백을 판정하려다 실패했는데(AUC 0.586), 분류 신뢰도는
**AUC 0.758**로 정답/오답을 구분한다. 예측대로 캘리브레이션이 낫다.

다만 위에서 보듯 이 신호를 검색 필터 해제에 쓰면 손해다. 폴백 판정에 쓰는 것은
별개 문제이며 아직 재지 않았다.

## 2차 효과

**재순위화의 이득이 남아 있는지 재측정이 필요하다.** 후보 20건이 모두 같은 의도가
되면 리랭커가 볼 변별 축이 하나 줄어든다. ADR-003에서 확인한 +3.00%p 중 의도 기여분은
사라질 가능성이 높다. `scripts/dump_pairs.py --intent-filter`로 입력을 덤프해 측정 예정.

**의도별 프롬프트 분기(대안 d)가 이 위에서 가능해졌다.** 분류 결과를 검색 필터와
프롬프트 선택에 동시에 쓸 수 있다.

그리고 이제 병목이 질환 축으로 옮겨갔다. 의도 0.8773은 분류기 정확도(0.8706)에
묶여 있으므로, 다음 개선 여지는 분류기 정확도이거나 필터로 잃은 질환 일치율 회복이다.
