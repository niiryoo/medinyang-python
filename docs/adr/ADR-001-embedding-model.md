# ADR-001: 임베딩 모델 교체 (ada-002 → text-embedding-3-small)

## 관측

`EMBEDDING_MODEL_NAME = "text-embedding-ada-002"` ([config.py](../../config.py)).
2022년 12월 모델이며, 2024년 1월에 나온 3세대가 **더 싸고 더 정확하다.**

추가로 `DB_PATH = "db"`가 존재하지 않는 디렉터리를 가리키고 있었다.

## 원인

프로젝트 시작 시점의 기본값이 그대로 남았다. 임베딩 모델은 한 번 정하면
인덱스를 다시 빌드해야 바꿀 수 있어서, 재검토 비용이 다른 설정보다 높다.

## 고려한 대안

| 안 | 장점 | 단점 |
|---|---|---|
| (a) ada-002 유지 | 재빌드 불필요 | 5배 비쌈. 성능 열위 |
| (b) **text-embedding-3-small** | 1/5 가격, 성능 우위, 차원 동일(1536) | 재빌드 필요 |
| (c) text-embedding-3-large | 최고 성능 | 3072차원, 인덱스 2배, 6.5배 가격 |
| (d) 오픈소스 한국어 모델 (BGE-m3 등) | API 비용 0, 온프레미스 가능 | GPU 필요, 운영 부담. 이 프로젝트에 서빙 인프라 없음 |

## 결정

(b). 차원이 1536으로 같아 FAISS 인덱스 구조를 바꿀 필요가 없고, 가격은 1/5이다.

(c)는 인덱스가 2배가 되는데 이 코퍼스에서 그만한 이득이 있을지 불확실했다.
(d)는 GPU 서빙이 전제인데 이 프로젝트에는 그 인프라가 없다.

## 트레이드오프

**두 벡터가 호환되지 않으므로 인덱스를 통째로 다시 만들어야 한다.**
102,245건 임베딩에 약 48분, 비용 약 $2.7이 들었다.

그리고 **인덱스와 모델이 어긋나면 조용히 망가진다.** 좌표계가 다른 벡터끼리
거리를 재도 예외가 나지 않고 그럴듯한 오답이 나온다. 이 실패 모드가 위험해서
`DB_PATH`와 `EMBEDDING_MODEL_NAME`을 config에서 인접한 위치에 묶고 주석을 달았다.
평가 스크립트에는 `INDEX_MODEL` 사전을 두어 인덱스 이름으로 모델을 강제한다.

## 2차 효과

두 인덱스(`db_ada`, `db_3small`)를 모두 남겼다. 폐기하지 않은 덕분에
**논문 설정이 기준선으로 계속 살아 있고**, 이후 모든 실험을 논문 대비로 말할 수 있게 됐다.
722MB × 2의 디스크를 쓰지만, "논문 대비 +7.64%p"라는 문장을 만들 수 있는 값이다.

## 검증

골든셋 220건, 대응표본 비교.

| 지표 | ada-002 | 3-small | 차이 |
|---|---|---|---|
| Precision@5 | 0.4800 | 0.5264 | +4.64%p |
| 의도 일치@5 | 0.5555 | 0.5845 | +2.90%p |
| 질환 일치@5 | 0.8527 | 0.9091 | +5.64%p |
| MRR | 0.5581 | 0.6212 | +6.31%p |

의도 일치는 +2.90%p에 그쳤다. **임베딩 품질을 올려도 의도는 거의 안 움직인다**는
첫 번째 신호였고, 이후 ADR-002·003에서 같은 패턴이 반복된다.
