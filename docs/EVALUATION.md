# 검색 성능 측정 리포트

원본 논문 설정을 기준선으로 두고, 검색 파이프라인의 각 구성 요소를 교체하며 측정했다.

> 게재 시점 인덱스는 수작업 선별이라 재현 불가. 본 측정은 동일 데이터셋에서 재현 가능한
> 규칙으로 구성한 인덱스 기준이며, 절대값이 아닌 상대 비교로만 해석한다.

---

## 1. 측정 설계

### 코퍼스

AI Hub 「초거대AI 사전학습용 헬스케어 질의응답 데이터」의 감염성질환 답변 전량.

| 항목 | 값 |
|---|---|
| 답변 문서 | 102,008건 |
| 청킹 후 | 102,245건 (1000자 초과 237건만 분할, 99.77% 무변화) |
| 인덱스 크기 | 722MB (모델별 동일) |
| 빌드 시간 | 약 48분 / 인덱스 |

### 골든셋

질문 파일 86,352건에서 **의도 11종 × 20건 = 220건**을 층화 추출 (`SEED=42`).

정답 라벨은 `(disease_name, intention)` 조합이며 질문 JSON의 필드에서 그대로 얻는다.
사람이 라벨링한 게 아니라 데이터셋에 이미 있는 값이므로 라벨 노이즈가 없다.

### 지표: Precision@k

Recall@k를 쓰지 않았다. `(질환, 의도)` 조합당 정답 문서가 중앙값 160건이라
k=20에서 Recall이 거의 항상 1.0이 되어 변별력이 없다.

무작위 기대값은 160/102,008 = **0.0016**이다.

보조 지표로 **의도 일치율**과 **질환 일치율**을 따로 본다. Precision을 두 축으로 분해해야
어느 쪽이 병목인지 보인다.

### cut 크기 통제

재순위화 실험에서 흔히 나오는 오류 하나를 피했다. 재순위화 없는 Precision@20과
재순위화 후 Precision@5를 비교하면, 재순위화가 아무 일을 안 해도 수치가 오른다
(20개 중 5개를 고르는 행위 자체가 정밀도를 올린다).

**모든 실행에서 @5 / @10 / @20을 함께 보고한다.** 재순위화는 같은 20개를 재정렬만 하므로
@20은 dense와 반드시 같아야 하며, 이것이 측정 정합성 검사로 기능한다.

### 유의성 판정

같은 질의 집합에 두 설정을 적용한 **대응표본** 비교. 질의별 차이의 평균과 95% 신뢰구간을
구하고, 구간이 0을 포함하면 `구분불가`로 판정한다.

MDE(최소검출가능효과)를 함께 보고한다. **MDE보다 작은 차이는 이 표본 크기로 판별할 수 없다**는
뜻이며, 이를 명시하지 않으면 노이즈를 개선으로 읽게 된다.

## 3. 병목 진단

Precision@5는 질환과 의도를 동시에 맞혀야 오르는 지표다. 두 축을 곱해 보면
어느 쪽이 발목을 잡는지 나온다.

```
E4:  질환 0.9336 × 의도 0.5982 = 0.5585      실측 P@5 = 0.5564
```

거의 정확히 일치한다. **두 오차가 독립적으로 곱해지고 있다**는 뜻이다.

| 축 | E1 → E4 | E8 | 상태 |
|---|---|---|---|
| 질환 일치 | 0.8527 → 0.9336 | 0.8718 | 필터 도입으로 일부 반납 |
| 의도 일치 | 0.5555 → 0.5982 | **0.8864** | 해소 |

임베딩 교체(E2)도, 하이브리드(E3)도, 재순위화(E4/E5)도 의도 일치를 유의하게 못 올렸다.
세 번의 실험이 같은 결론을 가리켰다. **검색기 교체로는 풀리지 않는 문제였다.**

원인은 데이터 표현에 있었다. 의도 라벨이 본문 앞머리에 문자열로 녹아 있을 뿐,
질의와 문서의 의도를 대조하는 장치가 파이프라인 어디에도 없었다.

질의 의도 분류기(TF-IDF + 로지스틱 회귀)를 붙이고 `intention` 메타데이터로 필터링해
의도 일치율을 0.5982에서 0.8864로 끌어올렸다.

분류기 학습 규모를 늘리면 그대로 따라 올랐다. 처음 의도당 3,000건으로 자른 것이 손해였다.

| 의도당 표본 | 학습 표본 | 홀드아웃 정확도 | macro F1 |
|---|---|---|---|
| 1,000 | 11,000 | 0.8532 | 0.8526 |
| 3,000 | 30,517 | 0.8706 | 0.8766 |
| 6,000 | 52,507 | 0.8875 | 0.8945 |
| 12,000 (사실상 전량) | 84,459 | 0.9000 | 0.8996 |

의도 일치율(0.8864)이 분류기 정확도(0.9000)와 거의 같다. **분류기가 천장**이라는 뜻이다.

남은 개선 여지는 두 가지다.

- 분류기 정확도. 다만 혼동 쌍이 정의↔원인↔증상, 검진↔진단, 치료↔약물로
  전부 의미적으로 인접해, 라벨 정의가 겹치는 구간이 이 접근의 한계로 보인다
- 필터로 잃은 질환 일치율 (0.9336 → 0.8718) 회복

## 4. 표본 크기의 한계

| 비교 | MDE (Precision@5) | 2%p 검출에 필요한 골든셋 |
|---|---|---|
| E4 vs E2 | 3.89%p | 832건 |
| E5 vs E4 | 2.72%p | 409건 |
| E4 vs E1 | 6.26%p | 2,158건 |

220건으로는 2%p 수준의 차이를 판별할 수 없다. E5의 `구분불가`는
**"차이가 없다"가 아니라 "이 표본으로는 2.72%p 미만의 차이를 볼 수 없다"**로 읽어야 한다.

다만 E5는 비용이 3.5배이므로, 2.72%p 미만의 이득을 위해 지불할 값이 아니라는 결론은
표본 크기와 무관하게 성립한다.

## 5. 재현

```bash
python -m scripts.preprocess                        # zip -> data/answers.jsonl
python -m scripts.make_db                           # JSONL -> FAISS
python -m scripts.build_goldenset                   # 골든셋 220건
python -m scripts.train_intent                      # 의도 분류기
python -m scripts.evaluate --index db_3small --out docs/g220-E2-dense.json
python -m scripts.evaluate --index db_3small --intent-filter --out docs/g220-E6.json
python -m scripts.dump_pairs --intent-filter        # 재순위화 입력 덤프
# notebooks/rerank_colab.ipynb 를 Colab GPU 에서 실행
python -m scripts.compare docs/rerank-base.json docs/g220-E2-dense.json
python -m scripts.choose_threshold docs/rerank-base.json
```

원자료는 `docs/*.json`에 질의별 결과까지 포함해 두었다.
